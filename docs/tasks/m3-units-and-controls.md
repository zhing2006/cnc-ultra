# 里程碑 3：单位和操作

## 目标

车辆和步兵按原版的类型数据移动，玩家可以像在原版里一样选择单位、下达移动命令。视野和迷雾在这一步做，单位被选中和接到命令时也会回话。

## 原因

从这一步开始，游戏第一次能上手操作了。原版玩家最先感觉到的，就是选择、下命令和单位移动的手感，这些都要照原版来做（设计宪法第三条）。

## 范围

要做：

- 从原版移植车辆和步兵的类型数据，包括速度、转向速度、视野和造价。
- 车辆的朝向、转向和移动，步兵走路的动画。
- 单位被友军挡住时，按原版的规则等待或者绕开。
- 流场按目标分开。同一个目标的单位共用一个距离场，同一时间对同一个目标只算一次（技术宪法第五条）。给一部分单位下新命令时，别的单位正在用的距离场不受影响。没有单位再用的距离场要回收，显存不能随下令的次数一直增长。
- 下令以后，单位从哪个逻辑帧开始转向或出发，和原版一样。原版在命令执行后的下一个逻辑帧里当场算出路径，所以在原版尺寸的地图上，算距离场不能让单位比原版晚出发。地图变大以后，算距离场的时间会随路径变长而增加。在一张 256×256 格、需要绕远路的测试网格上实测这段延迟，写进本文件（技术宪法第十三条）。
- 点选、框选、移动命令和光标的形状（设计宪法第三条）。
- 原版快捷键里和选择、移动有关的部分。
- 视野和迷雾在 GPU 上计算。原版的迷雾揭开以后就不会再盖上。
- 视野的透视层。
- 解析和播放 AUD 音频，单位被选中和接到命令时的语音。

不做：

- 攻击和其他战斗，放在里程碑 4。
- 侧边栏、雷达和建造，放在里程碑 5。
- 飞机，放在里程碑 5。
- 适合几千个单位的选择方式，放在里程碑 8。

## 参考

原版源码在 `refs/source/cnc-tiberian-dawn/`：

- `UDATA.CPP` 和 `IDATA.CPP`：车辆和步兵的类型数据。
- `DRIVE.CPP` 的 `DriveClass::Start_Of_Move` 和 `DriveClass::While_Moving`：车辆的移动。
- `INFANTRY.CPP`：步兵的移动和动画。
- `FOOT.CPP` 的 `FootClass::Basic_Path`：不可进入的终点附近如何选取替代格子。`FINDPATH.CPP` 的 `Find_Path`：无法走到终点时保留已经找到的可行路径。
- `UNIT.CPP` 的 `UnitClass::Can_Enter_Cell` 和 `DEFINES.H` 里的 `MOVE_TEMP`、`MOVE_MOVING_BLOCK`：被挡住时的处理。
- `QUEUE.CPP` 的 `Queue_AI_Normal`，以及 `CONQUER.CPP` 的 `Main_Loop` 在 `Logic.AI` 之后才调用 `Queue_AI`：玩家的命令在哪个逻辑帧执行。`DRIVE.CPP` 的 `DriveClass::Start_Of_Move` 和 `INFANTRY.CPP` 的 `InfantryClass::AI` 在没有路径时当场调用 `Basic_Path`：单位接到命令以后从哪个逻辑帧开始动。
- `DISPLAY.CPP` 的 `DisplayClass::Select_These`：框选。
- `MOUSE.CPP`：光标。`CONQUER.CPP` 的 `Keyboard_Process`：快捷键。
- `MAP.CPP` 的 `MapClass::Sight_From`：视野。
- `AUDIO.CPP` 的 `Sound_Effect`：播放音效和单位的语音。

OpenRA 的 `OpenRA.Mods.Cnc/FileFormats/AudReader.cs`：AUD 格式，只用来对照。

单位的语音和音效在 `sounds.mix` 里，开工时把 `refs/cnc-gold/gdi/sounds.mix` 加进 `assets/dev/`。

## 验收标准

- 同一辆车在空地上走同一段直路，用的逻辑帧数和按原版数值算出来的一样。（自动测试）
- 一辆车原地转一整圈，用的逻辑帧数和按原版的转向速度算出来的一样。（自动测试）
- 在 scg08eb 上向远近不同的几个目标下令，单位开始转向或出发的逻辑帧和按原版规则算出来的相同。（自动测试）
- 两组单位分别走向两个目标，其中一组换目标时，另一组的距离场和行走不受影响，GPU 版和 CPU 版的校验和相同。（自动测试）
- 一个单位揭开的格子，和按 `MapClass::Sight_From` 的规则算出来的相同。（自动测试）
- AUD 的解码结果和 OpenRA 解出来的采样相同。（自动测试）
- 点选、框选、下命令的方式和光标的变化都和原版一致，单位接到命令会回话。（试玩检查）

## 开发约定

- 试玩入口是 `?demo=units`，使用 scg08eb 的地形，放置多种车辆和步兵，方便检查速度、转向、动画和分组命令。
- `Alt+Enter` 切换由页面发起的全屏，并在全屏时启用 Keyboard Lock，以接收原版编队快捷键。原版 `CONQUER.CPP` 的 `Keyboard_Process` 没有占用这个组合。全屏入口不增加面板或按钮，操作说明同步写入中英文 README。
- 保留后台暂停和手动暂停。
- 整组移动保留各类型的原版速度。单位不能因临时拥堵而在远处放弃命令。
- 流场池按内存预算设置容量。如果同时使用的不同目标超出容量，允许在池满时轮换计算，让部分目标暂时等待；这是原版地图下令后不额外等待的唯一容量例外。没有池满时，新命令不打断其他单位正在使用的距离场。

## 原版行为与实现边界

- 命令按 `CONQUER.CPP::Main_Loop` 和 `QUEUE.CPP::Queue_AI_Normal`，在当前逻辑帧的单位更新后执行。原版默认每秒 15 个逻辑帧，车辆按 `DRIVE.CPP::While_Moving` 累积速度后沿轨迹步进，慢速载具不一定每帧都改变像素位置。
- 不可进入的终点按 `FOOT.CPP::Basic_Path` 查找邻近合法格子。玩家点击的目标与实际寻路目标分别保存；路线由流场计算，不移植原版的 `Follow_Edge` 算法。
- 选择和编队属于本地界面状态，不参与模拟校验和。移动命令记录点击时的所选单位，之后改变选择不会改变已下达的命令。
- 可见但不能进入的格子显示禁止移动光标，迷雾里显示可移动光标。两种情况都下达命令并回话，依据 `TechnoClass::What_Action`、`DisplayClass::Mouse_Left_Up` 和 `FootClass::Active_Click_With`。

## 验收状态与性能

M3 待试玩验收，需确认原版操作手感和语音。

2026-10-24，NVIDIA GeForce RTX 5090 D，驱动 32.0.16.1664，Chromium 156.0.8078.4。256×256 网格中，第 128 列从第 0 行到第 253 行设为障碍，目标在另一侧；距离场经过 4 次逻辑更新收敛，按 15 Hz 推进约需 0.27 秒。

下表使用 GPU timestamp query，排除 shader 编译、CPU 提交和状态读回。流场场景使用两万条相同目标记录，不代表两万单位的完整模拟。

| 测量范围 | GPU 耗时 |
|---|---|
| 上述绕路网格的 4 次逻辑更新 | 每次约 0.59 ms |
| 距离场收敛后的下一次更新 | 0.52 ms |
| 256×256 网格上，一万辆中型坦克首次揭图后的静止视野更新 | 0.07 ms |
| 同一批坦克全部向东移动一格后的视野更新 | 0.92 ms |

流场池容量为 64，distance、scratch 和 next 各占 16 MiB，共 48 MiB。整局 Ultra 帧率和驱动侧显存峰值未实测。
