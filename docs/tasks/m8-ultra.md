# 里程碑 8：Ultra 模式

状态：完成。NVIDIA、AMD 双 GPU 自动验收和项目负责人试玩验收均已通过。

## 目标

两个 AI 指挥官各带几千个单位，在里程碑 7 生成的大地图上会战（产品宪法第四条第三点）。两万个单位同时作战时，开发机上保持每秒 60 帧（产品宪法第七条第三点）。

## 原因

这是整个项目要展示的东西，用原版的像素素材打一场上万个单位的仗（产品宪法第三条）。只有规模变大才会出现的问题都在这一步解决，比如几千个单位怎么选择、镜头拉远以后怎么画、上万次开火的声音怎么处理。

## 范围

要做：

- 在 `?mode=ultra` 接入生成地图的模拟，检查寻路、占位、建造及场景初始化中的地图尺寸假设，再放置部队和补给设施。里程碑 7 只完成静态地形和部署空间验证。
- 左侧为黄色 GDI，右侧为红色 Nod，各自预置一万个单位，包含本阵营的各类作战兵种。两军前沿之间预留 24 格。地面部队按移动速度排列，快的在前，慢的在后。飞机从最后排起飞，向敌方推进。
- 允许预置直升机坪等必要的补给设施，让空军按原版规则补充弹药，开打以后不再造兵。海上使用原版炮艇沿固定路线往返支援，气垫艇按原版流程登陆，不增加可以自由指挥的舰队规则。
- 双方部队开局向敌方推进、交战。AI 指挥官在 CPU 上下达开局命令，推进和交战由 GPU 上的 Ultra Hunt 完成（设计宪法第五条）。玩家始终控制左侧黄方，可以不下令观看，也可以随时点选或框选部队重新下令，AI 不覆盖玩家的命令。操作和单位行为沿用标准模式，不设接管模式。
- 镜头可以拉远到看见整张地图。缩小到 1 倍以下时仍然显示原版精灵，使用最近邻采样，不替换成标记或图标。远景要分得清阵营，看得出战线在哪里（设计宪法第六条）。
- 同类的音效合并，或者限制同时播放的数量（设计宪法第六条）。
- 选择和编队沿用原版的点选、框选和编队快捷键，支持上万个单位的选择和下令，不增加 Ultra 专用的操作方式（设计宪法第四条）。
- 直接使用 M7 的 `?mode=ultra` 入口。新增控制面板放在原版界面之外，只保留缩放和 1×、10× 播放控制（设计宪法第七条）。地图种子和尺寸继续通过 URL 复现。
- 验证空军往返补给、炮艇沿岸支援和气垫艇登陆，位置不合适时调整地图与部署，不修改原版单位的数值和行为。
- 完成 NVIDIA、AMD 双 GPU 验收，包括里程碑 7 因设备缺失而未执行的检查。在开发机上实测帧率，达不到每秒 60 帧时做优化。

不做：

- 联机（产品宪法第五条）。

## 验收标准

- 开局以后双方的地面部队朝正前方推进，在两军之间碰头交战，形成南北走向的战线。（试玩检查）
- 两万个单位跑同样的逻辑帧数，GPU 版和 CPU 版的校验和相同。（自动测试）
- 两万个单位同时作战，开发机上保持每秒 60 帧。实测数据写进本文件，写明 GPU、浏览器和它们的版本（技术宪法第十三条）。（手动测量）
- 镜头拉到最远时能看到整张地图，分得清阵营，也看得出战线在哪里。（试玩检查）
- 上万个单位同时开火时，声音没有叠成一片噪音。（试玩检查）


## 验收证据

2026-10-27，在 Windows 11 Pro（Build 26300）、AMD Ryzen 9 9950X 上完成检查。两张显卡都核对了实际使用的 WebGPU adapter。

| 显卡 | 驱动 | 双 GPU 检查使用的浏览器 |
|---|---|---|
| NVIDIA GeForce RTX 5090 D | 32.0.16.1664 | Chromium 156.0.8078.4 |
| AMD Radeon(TM) Graphics（RDNA 2 集显） | 32.0.21042.62 | Chromium 156.0.8078.4 |

`pnpm check` 无错误或警告，`pnpm test` 的 54 个文件、901 项测试通过，`pnpm build` 通过。完整浏览器套件每卡覆盖 41 组，相关 6 组的最终结果来自复测，合并后两卡均为 41/41 通过。复测包括战役入口、原版寻敌、单位控制、海军流程、两万单位对照和实际战场性能。M7 留下的两张显卡上的地图与缩放检查也已经通过。

两万个单位在第 1、8、20、28 tick 与 CPU 参考版逐位相同，覆盖了敌军距离场的重算与切换，以及 9,995 个己方单位的框选、编队召回、移动和停止。NVIDIA 与 AMD 的四个校验和相同。两艘迎面交错的炮艇另有 80 tick 的逐位对照。两卡的联合兵种流程都在第 1928 tick 达成检查条件：双方地面部队已经开火，炮艇已经开火，十名乘员完成登陆，五架飞机完成补弹。

性能检查使用 1920×1080 视口、整图缩放和 1× 播放。每段记录 600 个实际绘制帧，声音已经解锁；GPU 计时另取 50 个完整逻辑 tick 及其绘制样本。浏览器由 Playwright 以 headless 模式启动。NVIDIA 还使用本机 Chrome 156.0.8078.47 测到了第 1800 tick 之后。

| 显卡与浏览器 | 开局平均 FPS | 交战样本 tick | 交战平均 FPS | 交战帧耗时 P95 | 实际逻辑速度 |
|---|---:|---|---:|---:|---:|
| RTX 5090 D，Chrome 156.0.8078.47 | 147.94 | 1803–1863 | 149.30 | 7.42 ms | 1.00× |
| RTX 5090 D，Chromium 156.0.8078.4 | 149.32 | 402–462 | 149.67 | 7.24 ms | 1.00× |
| AMD 集显，Chromium 156.0.8078.4 | 29.29 | 401–554 | 25.31 | 100.29 ms | 0.43× |

开局样本全程存活两万个单位。Chrome 的后段样本从 19,325 个存活单位降到 19,306 个。NVIDIA 开发机达到了 60 FPS 要求；AMD 集显通过了功能和确定性检查，但是没有达到 60 FPS，也不能维持 1× 逻辑速度。产品宪法的性能目标以 NVIDIA 开发机为准。

| GPU 计时项目 | RTX 5090 D，Chrome 156.0.8078.47 | AMD 集显，Chromium 156.0.8078.4 |
|---|---:|---:|
| 每个逻辑 tick 的 compute 平均耗时 | 3.98 ms | 102.42 ms |
| 绘制平均耗时 | 1.16 ms | 13.11 ms |
| 其中精灵 pass 平均耗时 | 1.01 ms | 4.34 ms |

场景保留了乘员槽和空精灵实例：共 30,892 个模拟槽、2,107,114 个精灵实例。上表已经包含这些成本。流场相关 storage buffer 的申请量为 6,895,948 字节，实际驻留显存未实测。Chrome 的交战样本中，同时发声最多 16 个，同类声音最多 3 个。

结果文件：

- `test-results/m8-final-acceptance.json` 汇总最终覆盖结果，并引用完整套件和复测报告。
- `test-results/nvidia/m8-determinism.json`、`test-results/amd/m8-determinism.json` 保存逐位对照和联合兵种检查结果。

试玩入口为 `http://127.0.0.1:5173/?mode=ultra`。项目负责人于 2026-10-27 确认操作手感、远景战线和声音听感验收通过。
