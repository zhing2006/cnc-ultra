# 里程碑 2：GPU 模拟框架

## 目标

搭好模拟的骨架，包括定点数、逻辑帧循环、命令和读回、随机数、状态校验和、格子占位和流场寻路。每个系统都同时写 CPU 版和 GPU 版，两边逐位一致（技术宪法第十五条）。做完以后，几百个单位能在 scg08eb 上找路、占格子。

## 原因

GPU 模拟是整个项目里最没有把握的部分，后面所有的游戏规则都建在这个框架上。整数定点数的 compute kernel 好不好写，几个单位同时抢一个格子时结果能不能确定，读回的延迟会卡住哪些逻辑，都要在这一步弄清楚。如果这条路走不通，要在写游戏规则之前就知道。

里程碑 1 的渲染管线由 CPU 写物件列表，并在 CPU 上建合成用的空间索引，这只适合不动的东西。单位动起来以后，位置在 GPU 上，绘制顺序和空间索引也要放到 GPU 上算。否则每一帧都要把所有单位读回 CPU 重新整理，这正是技术宪法第四条要避免的。

## 范围

要做：

- 定点数运算，TypeScript 和 TSL 各写一套，结果逐位相同。
- 逻辑帧循环，频率按原版的游戏速度来定（技术宪法第七条），渲染帧和逻辑帧分开。
- 模拟状态放在 storage buffer 里（技术宪法第四条）。CPU 把命令交给 GPU，需要读回的数据异步读回，结果至少晚一帧到达。
- 随机数（技术宪法第十六条）。
- 模拟状态的校验和。GPU 版算出校验和以后读回，和 CPU 版的比较。
- 格子占位（技术宪法第五条）。一格只能停一辆车，步兵占一格里的五个位置之一，几个单位同时要进同一格时，按技术宪法第六条裁决，被挡住的单位停下来等。
- 流场寻路，同一个目标的单位共用距离场。可通行性按原版地表类型、覆盖层，以及树木和建筑的实际占格来算。
- 流场的叠加层，在地图上画出每一格的流向。
- 地图尺寸是参数（技术宪法第十七条）。
- 单位的精灵实例由 compute pass 按模拟状态直接写进渲染用的 storage buffer，CPU 不逐个改写单位的实例数据（技术宪法第四条）。每个渲染帧里 CPU 的工作量和单位数量无关。
- 地面图层的绘制顺序照原版：每个逻辑帧对整个图层按 `Sort_Y` 冒泡一趟，新加进来的物件按 `Sorted_Add` 插到排好的位置上。不能换成完整排序，因为原版每帧只冒泡一趟，单位快速交错时顺序要晚几帧才排好，完整排序画出来的遮挡会和原版不同。一趟冒泡相当于求一次前缀最大值，所以在 GPU 上也能并行算。原版的注释说这个顺序要在每台机器上保持一致，因为有逻辑依赖它，所以它算作模拟状态，CPU 版和 GPU 版要逐位相同。比较 `Sort_Y` 时先比 y 再比 x，不照搬原版把两个坐标打包成一个 32 位数的做法（技术宪法第十七条）。
- 合成用的空间索引每个逻辑帧在 GPU 上重建。合成时要按绘制顺序找到采样位置下方的物件。GPU 用原子操作并行写入索引时，同一个格子里的先后顺序不确定，所以合成不能依赖写入的顺序。
- 逻辑帧编号 `Frame` 交给渲染。隐形扭曲改用它算相位，并且照原版处理 `Frame` 为 0 的特例。
- 一个测试场景：在地图上放几百个单位，点一个位置，所有单位都往那里走。单位暂时用原版坦克的精灵，速度先用一个固定值。

不做：

- 单位类型的数值、转向和动画，放在里程碑 3。
- 被挡住以后按原版的规则等待或者绕开，放在里程碑 3。这一步被挡住的单位只是停下来等。
- 选择和下命令的操作方式，放在里程碑 3。测试场景里点一下，就是给所有单位下同一个命令。

## 参考

原版源码在 `refs/source/cnc-tiberian-dawn/`：

- `OPTIONS.CPP` 里的 `GameSpeed = TIMER_SECOND / TICKS_PER_SECOND`，以及 `CONQUER.CPP` 里用 `Options.GameSpeed` 设定帧间隔的地方。按这两处算，原版默认的游戏速度是每秒 15 个逻辑帧。
- `CELL.H` 里 `Occupy` 的各个标志位，以及 `CELL.CPP` 的 `CellClass::Spot_Index`：格子占位和步兵的五个位置。
- `UNIT.CPP` 的 `UnitClass::Can_Enter_Cell`、`INFANTRY.CPP` 的 `InfantryClass::Can_Enter_Cell`，以及 `DEFINES.H` 里 `MOVE_OK`、`MOVE_TEMP` 和 `MOVE_MOVING_BLOCK` 这些结果：单位能不能进一个格子。
- `CDATA.CPP`：地形模板的地表类型。
- `FUNCTION.H` 的 `Random_Pick` 和 `Coord_Cell`：原版的随机数和坐标的位打包，只用来对照，不照搬（技术宪法第十六条和第十七条）。
- `CONQUER.CPP` 的 `Main_Loop`：每个逻辑帧调用一次 `Map.Layer[LAYER_GROUND].Sort()`，并且把 `Frame` 加一。`LAYER.CPP` 的 `LayerClass::Sort` 和 `LayerClass::Sorted_Add`，以及 `OBJECT.H` 里按 `Sort_Y` 比较的运算符：地面图层的绘制顺序。
- `CONQUER.CPP` 的 `CC_Draw_Shape` 和 `KEYFBUFF.ASM` 的扭曲初始化：隐形扭曲怎样用 `Frame`。

## 验收标准

- 定点数的每一种运算，TypeScript 版和 TSL 版对同一组输入算出相同的结果。（自动测试）
- 在小地图上，流场给每一格算出的距离，和另外写的一个最短路径算法算出来的相同。（自动测试）
- 从同一个初始状态出发，执行同一串命令，GPU 版和 CPU 版跑完同样的逻辑帧数以后，校验和相同（测试宪法第五条）。（自动测试）
- 很多个单位同时抢同一批格子时，GPU 版和 CPU 版的结果仍然相同。（自动测试）
- 几百个单位走动时，每个逻辑帧冒泡以后，GPU 版地面图层的顺序和 CPU 版逐位相同。（自动测试）
- 单位走动的过程中，挑几个逻辑帧读回索引图，和 `tests/reference/paint.ts` 按 CPU 版的状态和顺序画出来的图逐像素相同。场景里摆几辆处在不同隐形状态的静止隐形坦克，让走动的单位从它们前面和后面经过。（自动测试）
- 点一个目标，几百个单位绕开障碍走过去，一格只停一辆车，被挡住的单位停下来等。（试玩检查）
- 打开流场的叠加层，能看到每一格的流向都指向目标。（试玩检查）
- 如果能找到另一家厂商的显卡，在那块显卡上跑确定性测试，也得到同样的校验和。（自动测试，在另一块显卡上运行）

## 开发约定

- 独立入口是 `?demo=simulation`，默认入口保留 scg08eb 的初始摆放。测试场景放置 320 辆可移动坦克，另外放置五辆显示状态不同的静止隐形坦克。左键第一次点击锁定鼠标，锁定后点击可通行的地面，向全部移动坦克下达命令。Esc 释放鼠标。
- 切换到后台或最小化窗口时暂停模拟，回来以后继续，不补算离开期间的时间。页面也提供暂停、恢复、重置和流场开关。
- 静态障碍按原版实际阻挡处理。建筑的图片范围、树冠和建筑底下的 bib 不直接作为占格范围。摧毁障碍、进入建筑和碾压行为留给后续里程碑。
- 逻辑频率是每秒 15 帧，测试坦克每帧移动 32 leptons。八方向流场采用整数距离，直行一格为 256，斜行一格为 362。斜向进入格子的通行判断沿用 `UnitClass::Can_Enter_Cell` 和 `DriveClass::Start_Of_Move`，不额外要求旁边两个正交格都为空。
- 被其他单位挡住时等待，不分配队形终点，也不尝试绕开其他单位。目标附近出现排队和拥堵属于这一步的范围，等待和绕行的原版规则在 M3 接入。

## 验收状态
