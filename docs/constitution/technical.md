# 技术宪法

版本 0.1.0，批准于 2026-10-24。

## 第一条 只用 WebGPU

渲染和模拟都只走 WebGPU，不做 WebGL 回退。因为模拟跑在 compute shader 上，而 WebGL 没有 compute shader，回退过去也跑不起来。浏览器不支持 WebGPU 时，页面显示一段说明，不尝试降级运行。

## 第二条 Three.js 和 TSL

渲染使用 Three.js 的 `WebGPURenderer`。着色器和 compute kernel 都用 TSL 编写，这样渲染和模拟用的是同一套工具，模拟算出来的 buffer 可以直接交给渲染使用。TSL 表达不了的部分写成 WGSL 函数，再接进 TSL。

## 第三条 调色板索引渲染

原版素材是 8 位的调色板索引图，进入 GPU 以后仍然保持索引的形式。精灵和地形存成单通道的索引纹理，调色板是一张 256×1 的纹理，由 fragment shader 查表得到颜色。阵营换色和原版一样使用 remap 表，先把索引换成另一个索引，再去查调色板。泰伯利亚矿的调色板动画只需要换调色板。阴影由 shader 把下面的像素重新映射成更暗的颜色，这也是原版的做法。所有单位共用一张图集，用 instancing 在一个 draw call 里画完。

## 第四条 模拟状态常驻 GPU

单位、子弹和地图格子这些模拟状态一直放在 GPU 的 storage buffer 里。compute shader 更新完以后，渲染直接读取同一块 buffer，数据不回到 CPU。只有必须由 CPU 做判断的时候，才读回少量数据。读回是异步的，结果至少要晚一帧才能拿到，所以依赖读回结果的逻辑必须能容忍这一帧的延迟。

## 第五条 CPU 和 GPU 的分工

数量多、逻辑统一的工作放在 GPU 上，包括流场寻路、泰伯利亚矿的生长、视野和迷雾、单位之间的推挤和碰撞，以及子弹和粒子。流场寻路对同一个目标只计算一次距离场，推挤和碰撞用空间哈希查找邻近的单位。数量少、分支多的逻辑留在 CPU 上，包括玩家命令、AI 指挥官和建造。

## 第六条 确定性

同样的初始状态加上同样的命令序列，在任何显卡上都要得到完全相同的模拟结果，回放和以后的联机都依赖这一点。不同显卡上的浮点运算结果可能有细微差别，所以模拟只用整数定点数，原版的游戏逻辑本来也是整数运算。渲染不影响模拟结果，可以使用浮点数。多个线程写入同一个位置时，结果不能取决于线程执行的先后，必须用确定的规则来裁决，比如让编号较小的单位胜出。

## 第七条 逻辑帧和渲染帧分开

模拟按固定的逻辑帧推进，逻辑帧的频率和原版的游戏速度对齐。渲染帧和逻辑帧分开，所以显示器的刷新率不同，也不会改变游戏的速度。

## 第八条 引擎层和游戏层

代码分成两层。引擎层在 `src/engine/`，包括渲染、GPU 模拟框架，以及流场、空间哈希这类通用系统。引擎层从零写起，不包含从原版或者其他 C&C 项目移植过来的代码，也不引用游戏层。游戏层在 `src/game/`，包括 C&C 特有的全部内容，比如文件格式、游戏规则、AI 和界面。游戏规则从 EA 公开的原版源码移植过来，游戏层可以引用引擎层。

这样分层有两个原因。第一，引擎层不含移植代码，版权完全属于本项目的作者，以后可以单独拿出去使用，许可证也可以另外决定。第二，引擎层写成通用的形式以后，开发引擎时不需要去读原版源码，每个任务的边界也更清楚。

## 第九条 许可证

项目采用 GPL-3.0-or-later。游戏层里移植过来的代码出自 EA 以 GPL v3 发布的源码，所以还要遵守 EA 在 GPL 第 7 条下附加的条款：不得使用 EA 的商标，不得声称和 EA 有关联，修改过的版本要标明是修改版，并且保留 EA 的版权声明和这些附加条款。移植过来的代码要在注释里写明它在原版里的文件和函数。

## 第十条 原版数据在运行时读取

游戏在运行时直接读取原版的 MIX 文件，由游戏层的格式解析器解出图像、调色板、地图和声音。转换或者解包以后的原版素材不入库，因为它们仍然是 EA 的素材，入库就等于分发。测试用的参考图是例外。这样做还有一个好处：以后换成自己的素材时，只需要换掉数据的来源。

## 第十一条 依赖

在互相不冲突的前提下，依赖都使用最新的版本，并且写死版本号。新增依赖要先经过同意。

## 第十二条 验收

每个任务完成时都要能在浏览器里运行，并且能看到结果。测试的要求见[测试宪法](testing.md)。

## 第十三条 性能数据

性能数据必须是实测得到的，并且写明 GPU、浏览器和它们的版本。没有测过的，写“未实测”。

## 第十四条 纯静态部署

游戏不需要后端。`pnpm build` 产出的是一组静态文件，渲染和模拟都在玩家的浏览器里运行，所以任何静态托管都能部署。存档和回放保存在浏览器本地，或者导出成文件。如果以后要做联机，需要一个信令服务器帮双方建立连接，这是唯一需要服务器的部分。

部署时要满足下面几点：

1. 页面通过 HTTPS 或 localhost 访问，因为浏览器只在安全上下文里提供 WebGPU。
2. 资源使用相对路径，这样站点可以放在任意子路径下。
3. 页面要跨源隔离，服务器必须返回 `Cross-Origin-Opener-Policy: same-origin` 和 `Cross-Origin-Embedder-Policy: require-corp` 两个响应头，因为 SharedArrayBuffer 和 Worker 之间的共享内存都依赖跨源隔离。开发服务器和 preview 的这两个响应头配置在 `vite.config.ts` 里。在跨源隔离下，页面只能加载其他域名上返回了允许跨源嵌入响应头的资源，所以不要随意引用外部资源。
4. 原版素材不打进构建产物。部署时把原版 MIX 文件和构建产物放在同一个站点上，游戏在运行时读取它们。这样的站点只能在内部网络里使用，见产品宪法第六条。
