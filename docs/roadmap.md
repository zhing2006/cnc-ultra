# 路线图

路线图把产品宪法第四条规定的垂直切片拆成十个里程碑，从里程碑 0 到里程碑 9，按顺序完成。每个里程碑做完都要能在浏览器里看到结果（技术宪法第十二条），检查过以后再开始下一个。每个里程碑的任务单放在 `docs/plans/` 里，每个任务写明要做什么、对照原版的哪些文件和函数，以及怎么验收。

## 为什么按这个顺序

里程碑 0 从原版的 MIX 文件一直打通到屏幕，格式解析、GPU 纹理和 TSL shader 都要走一遍。阵营换色和单位的阴影也在这一步做，因为阴影要读底下像素的索引，它决定了整条渲染管线的样子。后面的任务都照着这一步的代码来写，引擎层和游戏层怎么分，TSL 怎么写，测试怎么写，都以它为样板。

GPU 模拟是这个项目里最没有把握的部分。用 TSL 写整数定点数的 compute kernel 顺不顺手，几个单位同时抢一个格子时怎么保证结果确定，读回的延迟会影响哪些逻辑，这些都还没有验证过。所以原版的画面一画出来，里程碑 2 就搭模拟框架，之后的游戏规则都建在这个框架上。如果这条路走不通，越早发现越好。

Ultra 模式和原版地图用的是同一套规则（设计宪法第五条），所以先在原版地图上把规则做完整，再放大规模。有些问题只有规模变大才会出现，比如几千个单位怎么选择、镜头拉远以后怎么画、上万次开火的声音怎么处理，这些留到 Ultra 的里程碑里解决。两万个单位能不能保持每秒 60 帧，也在那个里程碑里验收。

## 贯穿各个里程碑的做法

- 每个在 GPU 上运行的模拟系统，都和它的 CPU 版一起写，两边逐位一致（技术宪法第十五条）。模拟里的随机数按第十六条来算，地图尺寸按第十七条不写死。
- 流场、视野和矿区密度这三层透视视图，分别跟着对应的系统一起做，在里程碑 2、3 和 5 里。开发的时候它们也是调试工具，比如单位走错了路，打开流场的透视层看一眼箭头，就知道问题出在哪里。
- SHP 和地形模板的解码，对照 OpenRA 的 `--png` 命令导出的图（`OpenRA.Mods.Common/UtilityCommands/ConvertSpriteToPngCommand.cs`）。画面怎么叠加按原版源码来写，叠出来的效果在试玩时检查，整幅画面不和原版游戏的截图做对照。

## 里程碑

### 里程碑 0：调色板管线

把 GDI 的任务地图 scg08eb 的地形和单位画出来，定下调色板索引渲染的管线（技术宪法第三条）。第一张图用任务地图，因为多人地图上没有预先放好的单位。

- MIX、调色板、地形模板和 SHP 的解析器，以及地图的 INI 和 BIN 里地形、车辆和步兵这几部分。游戏在运行时从站点上读取原版的 MIX 文件（技术宪法第十条和第十四条）。
- 渲染管线，包括索引图、调色板纹理、阵营换色的 remap 表和单位的阴影。remap 表是 `CONST.CPP` 里的 `RemapYellow` 这些表，每个阵营用哪一张见 `HDATA.CPP`。原版画阴影时，先读出底下像素的索引，再通过 `UnitShadow` 表换成更暗的颜色（`TECHNO.CPP` 里画单位的 `CC_Draw_Shape`）。WebGPU 不能在同一遍里读正在写的像素，所以管线要为这一步留出位置。
- 车辆和步兵按地图里写的位置和朝向画出来，镜头固定不动。

验收：

- 打开页面能看到 scg08eb 的地形和单位，GDI 和 Nod 的单位颜色分得清，单位的阴影压暗了底下的地面。
- SHP 和地形模板的解码结果和 OpenRA 导出的图逐像素一致。

### 里程碑 1：原版画面

把 scg08eb 上的其他东西也画出来，镜头可以移动。

- 覆盖层（泰伯利亚矿和围墙）、弹坑、树木这类地形物件和建筑，以及它们的阴影。
- 隐形坦克的扭曲效果（`SHAPE_PREDATOR`），它和阴影一样要读底下的像素。
- 水面的调色板循环（`CONQUER.CPP` 的 `Color_Cycle`）。
- 镜头可以滚动，可以按整数倍放大（设计宪法第二条）。

验收：

- scg08eb 上的所有东西都按地图画了出来，镜头能滚到地图的每个角落。
- 放大到 2 倍和 3 倍时，像素仍然是方方正正的，没有模糊。

### 里程碑 2：GPU 模拟框架

搭好模拟的骨架。几百个单位在原版地图上找路、占格子，CPU 版和 GPU 版算出同样的结果。

- 定点数运算，TypeScript 和 TSL 各写一套，结果逐位相同。
- 逻辑帧循环。逻辑帧的频率按原版的游戏速度来定（技术宪法第七条），原版的定义见 `DEFINES.H` 的 `TICKS_PER_SECOND`，以及 `CONQUER.CPP` 里使用 `Options.GameSpeed` 的地方。
- 模拟状态放在 storage buffer 里（技术宪法第四条）。CPU 把命令写进命令队列交给 GPU，读回通过异步的环形缓冲，结果至少晚一帧到达。
- 随机数（技术宪法第十六条）。
- 模拟状态的校验和。GPU 算出整份状态的校验和，读回以后和 CPU 版比较。确定性测试（测试宪法第五条）从这里开始写。
- 格子占位（技术宪法第五条）。一格只能停一辆车，步兵占一格里的五个位置之一，几个单位同时要进同一格时，按技术宪法第六条裁决。
- 流场寻路，同一个目标只算一次距离场，流场的透视层也在这里做。可通行性先按地形模板的地表类型来算。

验收：

- 在 scg08eb 上放几百个单位，暂时用原版坦克的精灵。点一个目标，单位绕开障碍走过去，一格只有一辆车，被挡住的单位会停下来等。
- 打开流场的透视层，能看到箭头指向目标。
- 执行同一串命令，GPU 版和 CPU 版跑同样的帧数以后，校验和相同。如果能找到另一家厂商的显卡，在那块显卡上也要跑出同样的校验和。

### 里程碑 3：单位和操作

车辆和步兵按原版的数值移动，玩家可以像在原版里一样选择单位、下达移动命令。

- 车辆和步兵的类型数据从原版移植（`UDATA.CPP` 和 `IDATA.CPP`），包括速度、转向速度、视野和造价。
- 车辆的朝向和转向，步兵走路的动画。
- 鼠标的选择、框选和命令，光标的形状，以及原版的快捷键（设计宪法第三条）。
- 视野和迷雾在 GPU 上计算，视野的透视层也在这里做。原版的迷雾揭开以后就不会再盖上。
- AUD 音频的解析和播放，单位被选中和接到命令时的语音。

验收：

- 同一辆车在空地上走同一段直路，用的逻辑帧数和按原版数值算出来的一样。
- 选择、框选和下命令的方式和原版一致，单位接到命令会回话。

### 里程碑 4：战斗

地面单位之间按原版的规则交战。

- 武器和弹头的数据从原版移植（`CONST.CPP` 的 `Weapons` 和 `Warheads`），伤害按 `COMBAT.CPP` 的 `Modify_Damage` 计算。
- 攻击命令、自动选择目标和还击、射程、射速，以及炮塔的转向。
- 子弹、爆炸和弹坑。子弹和粒子在 GPU 上运行（技术宪法第五条）。
- 单位被摧毁时的爆炸和死亡动画。
- 武器和爆炸的音效。

验收：

- 两队单位交战，造成的伤害和摧毁一个单位用的时间，和按原版公式算出来的一样。
- 很多颗子弹同时打中同一个单位时，GPU 版和 CPU 版的结果仍然逐位相同。

### 里程碑 5：经济和建造

从一辆 MCV 开始造出基地，采矿，生产单位。

- 泰伯利亚矿的生长和蔓延在 GPU 上计算（`MAP.CPP` 的 `MapClass::Logic`），矿区密度的透视层也在这里做。
- 采矿车找矿、采矿，装满以后回精炼厂卸货（`UNIT.CPP` 的 `UnitClass::Harvesting` 等）。
- 资金、电力、建筑的放置规则、MCV 展开、工厂生产和建造队列，以及建筑的修理和出售。建筑的数据从 `BDATA.CPP` 移植。
- 原版界面里的侧边栏和雷达（设计宪法第七条）。
- EVA 的语音提示。

验收：

- 从一辆 MCV 开局，展开、造电厂和精炼厂、采矿、造兵，价格和建造时间都和原版一致。
- 矿区按原版的规则生长，打开矿区密度的透视层能看到每一格的矿量。

### 里程碑 6：原版地图上的一局对战

在原版的多人地图上，从开局一直打到分出胜负（产品宪法第七条第一点）。

- 电脑对手从重制版的 AI 移植（重制版 `HOUSE.CPP` 的 `Expert_AI`、`AI_Building`、`AI_Unit` 这些函数，由 `USE_RA_AI` 控制），规则和数值仍然以 1995 年的原版为准（设计宪法第一条）。
- 补齐科技树。多人模式下能造的单位和建筑都要能造，包括直升机坪造的 Orca、Apache 和 Chinook，离子炮和核弹这两种超级武器，以及工程师占领建筑、突击队放炸药、运兵车装载步兵、隐形坦克隐身这些单位的能力。科技等级固定开到最高。宝箱、夺旗和空袭不做。
- 开局前选择地图和阵营，判定胜负，一局结束以后可以重新开一局。

验收：在 scm01ea（Green Acres）上，玩家和电脑各从一辆 MCV 开局，一直打到一方被消灭，中途不刷新页面。

### 里程碑 7：地图生成器

用原版的温带瓦片生成 Ultra 模式用的大地图，要像原版设计师画的那样（设计宪法第九条）。

- 地图中间是一大片平原，留给两边会战。河流、山崖、树林和矿区放在战场的边上，或者零散地点缀在平原上，不生成很窄的通道。
- 整理出瓦片之间的拼接规则，也就是河岸、山崖、道路和海岸的边缘怎么接。拼接规则可以从原版的温带地图里统计出来。
- 矿区要靠近能建基地的平地。
- 地图尺寸在这个里程碑开始时定。
- 同一个种子生成同一张地图。

验收：

- 生成的地图上，所有瓦片的边缘都接得上。
- 生成的地图可以直接拿来打里程碑 6 的对战。

### 里程碑 8：Ultra 模式

在生成的大地图上，两个 AI 指挥官各带几千个单位开战（产品宪法第四条第二点）。

- AI 指挥官在 CPU 上运行（技术宪法第五条），负责几千个单位的分组、进攻和防守。里程碑 6 移植来的对手是为普通规模的对局写的，所以 AI 指挥官要另外写。
- 玩家可以旁观，也可以接管其中一方。
- 镜头可以拉远，缩小到 1 倍以下时换成远景的画法（设计宪法第六条）。
- 同类的音效合并，或者限制同时播放的数量。
- 大规模的选择和编队。具体的方案在这个里程碑开始时定，定下来以后写进设计宪法的偏离清单。

验收：

- 两万个单位同时作战，开发机上保持每秒 60 帧（产品宪法第七条第二点）。实测的数据写明 GPU、浏览器和它们的版本（技术宪法第十三条）。
- 镜头拉到最远时能看到整张地图，分得清阵营，也看得出战线在哪里。

### 里程碑 9：透视视图和对比场景

完成切片的最后两项（产品宪法第四条第三点和第四点）。

- 透视视图。三层透视都已经在前面的里程碑里做好了，这里统一它们的开关和配色（设计宪法第七条和第八条）。
- 对比场景。同一个场景，一边跑 CPU 版的模拟，一边跑 GPU 版，单位数量相同，两边并排显示帧率。CPU 版在 Worker 里运行，不能卡住主线程。CPU 版用几个线程，在这个里程碑开始时定，界面上要写明。

验收：

- 透视视图的每一层都能单独开关，打开以后照样能选择单位、下达命令。
- 对比场景里两边的单位数量相同，帧率并排显示，差距可以直接读出来。因为两边逐位一致，在同一个逻辑帧上，两边的画面相同。

里程碑 9 完成以后，切片按产品宪法第七条验收。
